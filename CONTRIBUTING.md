# Contributing to DocMind

DocMind is a portfolio project with no license granted for public reuse. Public visibility and this guide do not give permission to use, modify, or redistribute the project. See [LICENSE](LICENSE).

## Feedback and issues

Bug reports, documentation corrections, and focused feature suggestions are welcome through the issue templates. Before opening an issue, check for an existing report and describe the expected behavior, observed behavior, and a small reproducible example when relevant.

Do not upload real documents, credentials, API keys, private logs, or other sensitive data. Use synthetic samples. Follow the [code of conduct](CODE_OF_CONDUCT.md). For vulnerabilities, follow [SECURITY.md](SECURITY.md) instead of opening a public issue with details.

## Pull requests

Please contact the repository owner and obtain written permission and contribution terms before submitting code or documentation changes. Unsolicited pull requests may be closed. A pull request does not change the repository's copyright or grant anyone a license to use its contents.

For invited contributors:

1. Open a focused issue or agree on scope with the owner.
2. Work on a branch and keep each pull request limited to one change.
3. Add or update meaningful tests for behavior changes and update docs when behavior or setup changes.
4. Use synthetic data and confirm no secrets or real documents are included.
5. Complete the pull request template with the change, tests, and tradeoffs.

The owner reviews and decides whether to accept each contribution. No paid API or cloud resource should be created as part of a contribution without the owner's approval.
